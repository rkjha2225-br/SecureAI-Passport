# SecureAI Passport

**A security-focused AI action gateway built with Python, FastAPI, and React.**

SecureAI Passport is an AI security gateway that controls how natural-language requests interact with application actions. It introduces authentication, policy validation, human approval, and audit logging between AI interpretation and action execution.

## Overview

AI systems can interpret user requests, but allowing them to execute sensitive operations without proper authorization creates security risks.

SecureAI Passport addresses this problem by introducing a controlled execution layer.

Instead of allowing AI to execute actions directly, the system identifies a predefined action and passes it through backend security checks before execution.

## Features

- AI-powered natural-language request interpretation using Groq.
- API-key authentication.
- Separate approver-token authentication.
- Predefined action allowlisting.
- Human approval workflow for sensitive actions.
- Approval expiration and single-use approval consumption.
- Hash-chained audit logging.
- Audit event filtering and dashboard statistics.
- Input validation using Pydantic.
- Automated backend testing using Pytest.
- React-based security dashboard.
- Prompt-injection-resistant action interpretation instructions.

## Installation and Setup

### 1. Clone the repository

```bash
git clone https://github.com/rkjha2225-br/SecureAI-Passport.git
cd SecureAI-Passport
```

### 2. Create a Python virtual environment

```powershell
python -m venv .venv
```

### 3. Activate the virtual environment

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

If PowerShell blocks script execution, use the following command for the current terminal session:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

Then activate the environment again.

### 4. Install backend dependencies

```powershell
pip install -r requirements.txt
```

### 5. Configure environment variables

Set the following variables in PowerShell:

```powershell
$env:SECUREAI_API_KEY="your_actual_api_key"
$env:SECUREAI_APPROVER_TOKEN="your_actual_approver_token"
$env:SECUREAI_APPROVER_ID="approver-001"
$env:GROQ_API_KEY="your_actual_groq_api_key"
$env:SECUREAI_APPROVAL_TTL_SECONDS="3600"
$env:SECUREAI_MAX_PENDING="50"
```

Replace the placeholder values with your own credentials.

**Important:** Keep your real credentials private. Never commit `.env` or publish API keys and approver tokens to GitHub.

If you use a `.env` file, ensure your application loads it explicitly before relying on it. Setting environment variables in PowerShell as shown above avoids that dependency.

### 6. Run the backend

From the project root:

```powershell
python -m uvicorn app.main:app --app-dir backend --reload
```

The backend will run at:

```text
http://127.0.0.1:8000
```

API documentation:

```text
http://127.0.0.1:8000/docs
```

## Main API Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/health` | Health check |
| POST | `/actions/execute` | Process an authorized action |
| POST | `/ai/execute` | Interpret and process an AI request |
| GET | `/approvals` | View approval requests |
| POST | `/approvals/{id}/approve` | Approve a request |
| POST | `/approvals/{id}/reject` | Reject a request |
| GET | `/approvals/{id}` | Check approval status |
| GET | `/audit` | View audit events |

### Authentication Headers

Protected API endpoints use:

```text
X-API-Key: your_api_key
```

Approval and rejection endpoints additionally require:

```text
X-Approver-Token: your_approver_token
```

The approver identity is configured on the backend using `SECUREAI_APPROVER_ID`.

## Security Workflow

The system follows a controlled execution process:

1. The user submits a natural-language request.
2. The AI interprets the request and returns a predefined action.
3. The backend validates the returned action.
4. The gateway checks the action against the permission policies.
5. Sensitive actions require human approval.
6. The approval is validated before the simulated action is processed.
7. The system records relevant events in the audit log.

## Security Design

SecureAI Passport uses several security mechanisms:

- **Authentication:** API keys and a separate approver token.
- **Authorization:** Predefined action policies.
- **Human-in-the-loop control:** Sensitive operations require approval.
- **Approval lifecycle:** Pending requests can expire and approved requests can be consumed only once.
- **Auditability:** Events are recorded using a hash-chained audit log.
- **Input validation:** Pydantic validates incoming request data.

AI-generated output is treated as untrusted input. System instructions alone cannot guarantee protection against prompt injection.

## Current Limitations

- Customer-record deletion is simulated. No actual customer data is deleted.
- The approval system uses local JSON-file persistence.
- File-based persistence and in-process locking are not suitable for multi-worker production deployments.
- Hash chaining can help detect certain audit-log modifications, but does not guarantee tamper-proof storage.
- API-key and approver-token authentication is a demonstration mechanism, not a complete production identity-management system.
- Production deployment requires HTTPS, secure secret management, stronger identity controls, durable storage, and additional security testing.

**SecureAI Passport is an educational security prototype, not a production-ready security platform.**
